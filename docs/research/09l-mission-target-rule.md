## 290레벨 4.178%p 사례의 정체

청크의 `startLevel:290, startPercent:85.386` 표에 **1→2→3단계**가 각각 290·87.800%, 290·91.978%, 290·96.156%다. 두 간격은 모두 **4.178%p = 12,296,082,571,552.2 EXP**다.

다른 `startLevel:288, startPercent:72.212` 표에서는 17단계부터 290레벨이며 17→30단계 평균 간격은 **5.0045384615%p = 약 14.7286조 EXP**다. 표시 반올림으로 설명할 수 없는 차이다.

그러나 `startPercent`를 지정 당시 경험치라고 단정할 수 없다. 286 표의 값 26.617%는 1단계 목표 10.472%보다 높고, 292 표의 값 15.327%도 1단계 목표 8.878%보다 높다. 288 표는 시작값과 1단계 목표가 같다. 이 메타데이터로 지정 레벨 의존성을 확정하면 순환 추론이다. 표의 오기인지, 게임의 단계별 규칙인지도 원본 화면 없이 구분하지 못했다.

또한 같은 290 표의 291 구간은 **일정 간격 + 목표별 반올림**으로도 모두 맞지 않는다. 각 목표에 ±0.0005%p를 허용했을 때, 4→8단계는 간격 ≤4.596250%p, 8→25단계는 간격 ≥4.5962941176%p를 요구한다. 허용 구간이 겹치지 않는다. 중간 목표에 오기가 있거나, 일정 간격 이상의 규칙이 필요하다. 소수 표시 반올림을 무시한 단순 회귀만으로 실제 규칙을 확정하지 않았다.

## 입력·지급·저장 호환 규칙

- 성장 미션의 접힌 `그다음 목표도 넣기`: 체크를 켜고 두 레벨·%를 입력한다. 레벨마다 필요 경험치를 합쳐 두 목표의 raw 간격을 구하고, 이 경험치를 이후 단계에 반복한다. 꺼져 있으면 기존 자동 목표가 그대로다. 역순·동일 목표는 입력 오류를 알리고 기존 간격을 쓴다. 마지막 30단계만 남았을 때 두 목표 입력은 표시하지 않는다.
- PLUS `지금 PLUS 레벨`과 `그중 이미 받은 보상 레벨`을 구분한다. 받은 보상은 남은 수량을 별도로 넣는다. 받은 레벨은 현재 레벨 이하로 정리한다.
- `주간 획득 포인트`는 다음 목요일부터 주마다 더한다. 현재 레벨 안의 0~749포인트를 이월한다. 기준 주에 아직 받을 포인트는 접힌 입력으로 따로 받아 그 주 수요일에 더한다. 새로 열린 레벨의 보상만 지급한다. 10/21 마지막 포인트·수령을 포함하고 10/22 이후 시작이면 지급하지 않는다.
- 주간 계획을 목요일에 더하는 기존 계산 시점을 유지했다. 실제 주중 어느 날 미션을 달성하는지까지 새로 확인한 것은 아니다. 화면에는 계산 시점을 입력 안내로 명시한다.
- 옛 저장값에 현재 레벨이 없으면 저장된 기준일의 기존 최대 진행도와 750포인트 이월값으로 복구한다. 이미 받은 레벨을 낮추지 않는다. 현재 레벨만 새로 명시한 저장값에는 이전 최대 이월분을 섞지 않는다. 두 목표 입력은 기본 꺼짐이고 저장 후 복원된다.
- 기본 결과와 두 번째 계정은 10/9 기준으로 전후 동일: **290·31.7742538283%, 30단계** / **288·3.8957055428%, 18단계**. 기존 입력 180조합의 최종 위치·단계·경험치 내역도 모두 동일했다.
